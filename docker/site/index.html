The relay is running, but it is serving this default page instead of a real website. That is fine for a first test: a bridge request (GET /?bridge=<capability>) is still answered correctly.

Replace this before real use. The relay deliberately ships no public website, because many operators deploying the same starter page would give active probers a reliable fingerprint. Mount your own site over /srv/tproxy-site, or point the relay's public_upstream at an application on a loopback port.

Do not route static files or a site application around the relay on this hostname. The relay must stay the one gateway so that encoding, response headers, and method handling do not expose a separate transport surface.
